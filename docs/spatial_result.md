## Overview / Ringkasan

`Spatial Result` is the platform's standardized domain data contract for representing analytical outputs generated by computer vision and geospatial plugins (Module 02, Module 04, Module 07, Module 08, Module 10) on top of the interactive Leaflet map explorer (Module 03).

### Key Architectural Pillars

1. **RFC 7946 GeoJSON Standard**:
   - All spatial geometries (`Point`, `Polygon`, `LineString`) strictly adhere to **WGS 84 (EPSG:4326)** with `[Longitude, Latitude]` coordinate ordering.
2. **Dual-Storage Engine**:
   - Small to medium layers are persisted as single flat JSON files at `map_storage/spatial_results/{layer_id}.json`.
   - Massive datasets are saved in decomposed directories (`{layer_id}/layer.json` + `features/{feature_id}.json`) with hard 64 KB safety bounds per file.
3. **Atomic Write-Through & 2-Phase Quarantine**:
   - File mutation utilizes temporary file flush and atomic OS rename (`write_atomic`).
   - Deletions are quarantined in `.trash_sr_{layer_id}_{timestamp}/` with transactional rollback if layer deregistration fails.
4. **Layer State Auto-Sync**:
   - Every saved spatial result automatically generates and maintains its companion state in `map_storage/layers/{layer_id}.json`.
